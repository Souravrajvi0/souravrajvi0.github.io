Phase 0: Authentication & Security

Authentication is the process of verifying who someone is. In backend engineering, it forms the foundation of system security, user sessions, and API authorization.

1. What is Authentication?

Authentication verifies identity before granting access to resources. When a user logs in, the backend checks provided credentials against stored hashed values (such as bcrypt or Argon2 passwords).

2. Session-Based Authentication

Session-based auth uses server-side storage (e.g. Redis, database) to track logged-in users. When a user authenticates, the server stores a session object and returns a session ID cookie to the browser. 

User Login → Server Validates → Creates Session (Redis/DB) → Sets Cookie (Session ID)
Subsequent Request → Cookie attached → Server looks up Session ID → User Authenticated

PROS

  • Easy to invalidate single sessions
  • Stateful control over active logins
  • Payload hidden from client side

CONS

  • Server storage overhead
  • Requires shared cache for multi-server scaling
  • CORS cookie limitations for cross-domain APIs

3. Token-Based Authentication

Token-based auth relies on a signed token sent in HTTP headers (e.g. Authorization: Bearer <token>). The server validates the cryptographic signature without querying session databases. 

Client Login → Server Validates → Signs Token (Secret/PrivateKey) → Returns Token
Client Request → Sends Bearer Token in Header → Server Verifies Signature → Grants Access

4. JSON Web Tokens (JWT)

JWT (RFC 7519) is a standard format for securely transmitting claims as a Base64URL-encoded JSON object. A JWT consists of three parts separated by dots: 

Header.Payload.Signature

Header:    {"alg": "HS256", "typ": "JWT"}
Payload:   {"sub": "1234567890", "name": "Alice", "role": "admin", "exp": 1700000000}
Signature: HMACSHA256(base64UrlEncode(Header) + "." + base64UrlEncode(Payload), secret)

5. OAuth & OAuth 2.0 Framework

OAuth 2.0 is an authorization framework enabling third-party applications to access user resources securely without revealing passwords (e.g. "Login with Google/GitHub"). 

1. User clicks "Login with Provider"
2. Redirect to Authorization Server with Client ID & Scope
3. User approves permissions
4. Auth Server redirects back with Authorization Code
5. Backend exchanges Code for Access Token & Refresh Token
6. Access API with Access Token

6. Multi-Factor Authentication (MFA)

MFA requires two or more distinct factors before issuing tokens:

  • Knowledge: Password, PIN, or security question
  • Possession: TOTP App (Google Authenticator), SMS OTP, Hardware YubiKey
  • Inherence: Fingerprint, Face ID, or biometrics
